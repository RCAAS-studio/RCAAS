# RCAAS Feature Book: implementation comparison

Reviewed 15 November 2026 against the actual `docs/RCAAS-Feature-Book.pdf`, all 27 PDF pages. SHA-256: `0aae7011a133a4a670bcddfa285443d0a243e0c3a1723a909a6d787c870bc71d`. The cover identifies the 28 September 2026 edition; pages 19–27 add October updates. Page references below mean PDF page numbers, because some printed footers overlap.

Text was extracted from this binary with an already cached PDF reader in ignored QA storage, without adding a project dependency. Pages 1 and 5 were also rendered; page 5 was visually inspected. Extracted text, page records and rendered images are under `qa-bug-hunt/feature-book-*`. This comparison does not treat screenshots or descriptive claims as implementation evidence.

## Material discrepancies

| PDF claim | Current implementation and evidence | Disposition |
| --- | --- | --- |
| p12: editor “Autosave” | `studio/editor/DraftControls.tsx` requires **Save space**. Dirty state and leave protection exist; publishing saves a dirty draft first. Real browser testing verifies explicit save and publication, and component tests verify save-before-publish. | **Not implemented as documented:** general automatic server autosave. Keep explicit-save wording in current guides; do not add autosave during this audit. |
| p12: restore “any earlier save” | `publishing/PublishButton.tsx`, `routes/scenes.js` and `store.js` retain numbered **published snapshots**, not a new recoverable version for every ordinary save. | **Documentation overstatement.** Describe published-version history. |
| p16: S3 means “nothing is stored on the PC”; uploads stream “straight” into the bucket | `storage-s3.js` spools streams lacking a known length to temporary disk. Upload preparation/finalization uses staging and retains failed staging for retry; `routes/assets.js` and upload-policy tests cover this. | **Documentation overstatement.** Disk/staging capacity remains necessary with S3. No live R2 run is claimed. |
| p16/p18: another PC sees everything | Shared asset storage shares scans. Projects, drafts, bookings and sites remain JSON under the API's `DATA_DIR`; account PostgreSQL does not migrate those stores. The book's p18 centralized-API recommendation is still relevant. | **Conditional feature.** Multiple PCs need the same API/data service, not merely the same bucket. |
| p17: `src/app/(site)` and viewer/editor under `src/components`; older endpoint/test/build counts | Current routes are under `(marketing)`, complex UI under `src/features`, with named Studio modules. The Developer Guide generator currently inventories 103 API routes. This run has 262 passing unit/API tests, two skips, plus browser suites. | **Historical documentation.** Use current architecture guides and measured results. September and October counts are dated snapshots, not promises of current totals. |
| p25: the Contact action opens the visitor's email application | Current `marketing/pages/ContactPage.tsx` submits an enquiry through `submitEnquiry` / `sendLead` / `POST /api/leads`, with validation and an explicit result. | **Replaced behavior.** Preserve current functionality; do not restore an obsolete mailto flow. |
| p25/p27: old About register, nine How-it-works FAQs, old route naming | Current About/How We Work compositions, evidence gates and per-family schema differ; `/how-it-works` redirects to `/how-we-work`. | **Historical content.** Count current visible/resolved answers rather than assuming nine or reinstating old claims. |
| p27: “No tracking” | `lib/stats.ts` sends first-party visit, visible-time, hotspot-attention and intent beacons; reports depend on them. Lack of analytics cookies is a narrower claim than no measurement. | **Wording needs qualification.** Current privacy/cookie wording must describe first-party analytics accurately; no legal approval is claimed. |
| p15: secrets live “only in server/.env” | Runtime environment variables are also supported; production guidance keeps configuration separately protected. Tests use synthetic environment secrets. | **Deployment description is too narrow.** Never infer secret safety from a filename. |
| p4/p11: client/marketing presentation and dark-mode screenshots | Current company pages and client website looks evolved; the p22 appendix already says client looks no longer follow visitor dark mode. | **Historical visuals.** No redesign or theme restoration belongs in this architecture audit. |

## Feature-by-feature comparison

“Implemented but not fully verified” means code and relevant regressions exist, with the stated live/device/provider limits. It does not mean the feature is absent.

| Book area / PDF pages | Status | Current source / evidence and limits |
| --- | --- | --- |
| Platform surfaces, p3 | Completed and verified | Native company routes, authenticated project home/editor and anonymous `/t/<project>/<space>` redirect/tour exercised. `/s` routes remain server-rendered client sites. |
| Public website, p4 | Completed and verified for migration | All 42 listed URLs plus visible blog routes, titles/canonicals/noindex, aliases/404s, homepage/planner and enquiry navigation covered on root preview and `/RCAAS` export. Animation/performance on every physical device is not certified. |
| Gaussian tour and modes, p5 | Implemented but not fully verified | Genuine copied LCC2 capture reaches native instanced GPU rendering on desktop; anonymous published tour works. Movement/raycasting are in scene modules; all modes and physical touch interaction were not exhaustively exercised. |
| Languages/day-night/quality/sharing, p6 | Implemented but not fully verified | `lib/i18n.ts`, `scene/deviceTier.ts`, scene night links, tour/hub/embed routes and stats exist. Language-contract/API tests pass; native-language accuracy, every embed host and low-end-device quality behavior remain separate checks. |
| 360 video, p7 | Implemented but not fully verified | `studio/upload.ts`, `scene/panoModel.ts` and API range support exist. Genuine 360 footage was not part of this capture run; no raw INSV support is claimed. |
| Tour sales/enquiries, p8 | Implemented but not fully verified | Booking/enquiry features, published hotspot authorization and form/API tests exist. No real booking or delivery-provider side effect was triggered. |

No discrepancy was “fixed” by adding a feature, restoring an old UI, changing client data or silently rewriting the historical PDF. Current docs link this comparison so the dated book remains usable with its limitations visible.
